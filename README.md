# 문서 스캐너

사진 속 종이의 네 모서리를 찾아 투시 변환하고, 스캔본을 JPG 또는 PNG로 저장합니다. Python 3.12에서 검증했습니다.

## 실행

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py evaluation/images/front_02_letter001_frame_0072.jpeg
```

GUI는 `1. Original`(원본) → `2. Preprocessed`(전처리) → `3. Edges`(엣지) → `4. Contour`(윤곽선) → `5. Result`(스캔 결과) 순으로 표시합니다. `2. Preprocessed` 창의 슬라이더로 블러와 Canny 임계값을 조절합니다. `s`로 저장하고 `q` 또는 `Esc`로 종료합니다. 기본 저장 경로는 입력 사진 옆의 `사진_scanned.png`입니다.

| 슬라이더 | 범위와 단위 | 시작값 |
| --- | --- | --- |
| `Blur (2n+1)` | 표시값 `n`은 0부터 15까지입니다. 실제 가우시안 커널 한 변은 `2n+1`픽셀로, 1부터 31까지의 홀수입니다. | `n=1`, 커널 `3×3` |
| `Canny low` | 0부터 255까지 선택하는 밝기 변화 강도의 낮은 임계값입니다. | `25` |
| `Canny high` | 0부터 255까지 선택하는 밝기 변화 강도의 높은 임계값입니다. | `80` |

Canny는 `0 ≤ low < high ≤ 255`일 때 계산합니다.

창을 열 수 없는 환경에서는 명령줄에서 스캔본과 히스토그램을 저장할 수 있습니다.

```sh
python main.py '사진.jpg' --no-gui --output scan.png --histogram brightness.png
python main.py '사진.jpg' --no-gui --blur 5 --canny-low 50 --canny-high 150
```

`--no-gui`에서는 `0`이 저장 성공, `1`이 사진 읽기·설정·저장 오류, `2`가 문서 후보 미검출을 뜻합니다. 잘못된 명령줄 인수도 `argparse`에서 `2`와 사용법을 반환합니다. 오류 메시지는 표준 오류 출력에서 확인할 수 있습니다.

## Canny의 두 임계값

`low`와 `high`는 경계를 얇게 만든 뒤 각 위치에 남은 **밝기 변화의 크기**를 판단합니다. `high`보다 강한 위치는 경계를 따라가는 출발점이 됩니다. `low`보다 약한 위치는 제거되고, 두 임계값 사이에 있는 위치는 강한 경계까지 8방향 이웃으로 이어질 때 남습니다. 이 연결 판정을 **히스테리시스**라고 합니다. [OpenCV Canny 공식 설명](https://docs.opencv.org/4.x/da/d22/tutorial_py_canny.html)

기본 `low=25`, `high=80`에서 변화 크기가 `95 → 54 → 35`인 픽셀이 서로 이어져 있으면 세 픽셀이 모두 남습니다. 같은 `54`라도 강한 경계에 닿는 경로가 없으면 제거됩니다. `low`를 `40`으로 올리면 `35`가 끊기고, 주변에 다른 강한 경계가 없을 때 `high`를 `100`으로 올리면 `95`도 출발점이 될 수 없어서 이 경계 전체가 사라집니다. 이 때문에 설정을 높이면 잡음이 줄면서 희미한 종이 모서리도 함께 사라질 수 있습니다.

## 처리 과정

`main.py`는 사진 디코딩, 창 표시, 저장을 맡습니다. `scanner.py`는 창 없이 호출할 수 있는 이미지 처리를 맡고, `evaluate.py`는 같은 스캔 함수로 기준 모서리와 예측을 비교합니다.

| 함수 | 입력 | 반환값 |
| --- | --- | --- |
| `main.read_image` | 이미지 경로 `Path` | `(H, W, 3)`의 `uint8` 배열. 채널 순서는 BGR입니다. |
| `scanner.scan` | BGR `uint8` 배열과 `ScanSettings` | `ScanResult`. `original`과 `overlay`는 BGR 미리보기, `preprocessed`와 `edges`는 2차원 `uint8` 배열입니다. `corners`는 미리보기 좌표이고 `scanned`는 2차원 `uint8` 스캔본입니다. 후보가 없으면 두 필드는 `None`입니다. |
| `scanner.preprocess` | BGR `uint8` 배열과 홀수 블러 커널 크기 | `(회색조 원본, 블러 결과)`. 둘 다 `(H, W)`의 `uint8` 배열입니다. |
| `scanner.detect_edges` | 블러를 적용한 회색조 배열과 `low`, `high` 임계값 | `(H, W)`의 `uint8` 엣지 영상. 경계는 `255`, 나머지는 `0`입니다. |
| `scanner.find_document`, `scanner.order_corners` | 각각 `(H, W)`의 엣지 배열과 `(4, 2)`로 해석할 수 있는 점 4개 | 좌상부터 시계 방향으로 정렬한 `(4, 2)`의 `float32` 좌표. `find_document`는 후보가 없으면 `None`을 반환합니다. |
| `scanner.warp_document` | `(H, W)` 회색조 배열과 정렬한 `(4, 2)` 점 | `(출력 높이, 출력 너비)`의 평탄화 배열. 입력과 같은 픽셀 자료형입니다. |
| `main.save_image` | 출력 경로 `Path`와 이미지 배열 | 성공하면 `None`을 반환하고, 지원하지 않는 확장자나 저장 실패는 예외로 알립니다. |
| `evaluate.compare_outline` | 예측 점 4개, 기준 점 4개, 같은 좌표계의 `(H, W)` | `(IoU, 정규화한 최대 모서리 오차)` 두 실수. |

화면 좌표 `(x, y)`는 배열의 `image[y, x]`에 대응합니다. 컬러 배열에서 `image[y, x, 0]`은 파랑이고, 회색조 배열은 픽셀마다 밝기 하나만 저장합니다.

전처리와 엣지 검출을 분리해 회색조 변환과 블러의 결과, Canny가 경계로 표시한 위치를 각각 테스트할 수 있습니다. `scan()`은 두 단계를 연결하고 엣지 영상으로부터 문서 윤곽선을 찾습니다.

### 네 점 정렬과 투시 변환

1. 네 좌표의 평균으로 중심 `(cx, cy)`를 구하고 각 점의 `atan2(y - cy, x - cx)`를 정렬합니다. 화면의 `y`가 아래로 증가하므로 각도가 증가하는 방향은 시계 방향입니다.
2. 연속된 변의 외적 부호로 볼록성을 확인하고, `x+y`가 가장 작은 점부터 목록을 시작합니다. 합이 같으면 `y`가 더 작은 점을 선택합니다. 예를 들어 뒤섞인 `(180,40)`, `(40,155)`, `(60,30)`, `(205,165)`는 `(60,30)` → `(180,40)` → `(205,165)` → `(40,155)` 순서가 됩니다.
3. `getPerspectiveTransform`은 정렬한 원본 네 점과 출력 직사각형의 네 점을 받아 `3×3` 변환 행렬을 만듭니다. `warpPerspective`는 그 행렬과 출력 `(너비, 높이)`를 받아 픽셀을 채웁니다. 너비는 위·아래 변 중 긴 쪽, 높이는 왼쪽·오른쪽 변 중 긴 쪽의 픽셀 거리를 반올림해 구합니다. 원근 때문에 한쪽 변이 짧게 찍힌 경우에도 그 짧은 거리만 기준으로 출력 크기를 줄이는 일을 피할 수 있습니다.
